# parralelVdz5

## Что сделано
Сделал разбор логов, последовательный и параллельный анализ.
Файлы читаются разными потоками через пул.
Статистика потокобезопасная.
Есть семафор, атомарные счётчики, остановка через `volatile` и обработка битых файлов.

## Битые строки и файлы
Если строка битая, я её пропускаю и считаю как повреждённую.

Если файл не читается, он помечается как ошибочный, а остальные файлы продолжают обрабатываться.

## Частичный отчёт при остановке
Если анализ остановили, в отчёт попадает всё, что уже успели обработать:

- статистика по обработанным строкам;
- счётчики строк, битых записей и ошибок;
- список битых файлов;
- флаг остановки.

## Инварианты

1. Строка обрабатывается один раз.
   Один файл обрабатывает одна задача, у неё свой итератор, итератор не передаётся другим потокам.

2. `requests = successful + errors`.
   Каждая корректная запись попадает либо в успешные, либо в ошибки.

3. `maxDuration <= totalDuration`.
   Максимум берётся из тех же времён, которые плюсуются в общую сумму.

4. Активных файлов не больше лимита семафора.
   Счётчик растёт только после получения разрешения семафора.

5. После завершения активных файлов 0.
   На каждое увеличение есть уменьшение в `finally`.

6. Один битый файл не мешает остальным.
   Ошибка одного файла ловится отдельно, остальные продолжают обрабатываться.

7. Дедлока нет.
   Сначала берём разрешение семафора, потом читаем файл, потом обновляем статистику.
   Никто не ждёт семафор, удерживая блокировку.

## Почему нет дедлока
Порядок такой:

1. получить семафор;
2. читать файл;
3. обновить статистику.

Если статистика общая, используется один общий лок.
Если статистика по каждому URL, каждый блокирует только свой аккумулятор.

Семафор и завершение задачи освобождаются в `finally`, поэтому ничего не зависает.

## Зачем нужен `volatile`
Чтобы флаг остановки сразу видели все потоки.
Без `volatile` рабочий поток может продолжить работать со старым значением флага.

## Эксперименты
4 потока быстрее одного.

Семафор 4 быстрее семафора 1.

Блокировка по каждому URL лучше, когда разных URL много.
Если почти всё в один URL, разница небольшая.

Битные строки и файлы видны в счётчиках, но нормальные данные всё равно попадают в отчёт.
Если почти все запросы идут в один URL, разница небольшая, потому что потоки всё равно спорят за один и тот же аккумулятор.

### Битый файл или битая строка

Повреждённые данные видны в счётчиках.

При этом нормальные файлы и нормальные строки всё равно попадают в отчёт.
